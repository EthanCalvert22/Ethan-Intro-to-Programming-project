# Decisions

The brief leaves some things open. These are the choices made for Brew & Byte, each with a one-line reason. The rules themselves are written out in plain language in [`spec/RULES.md`](../spec/RULES.md).

## Rules and numbers

| #   | Decision                                                                                                                                                                                                                                       | Reason                                                                                                                   |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 1   | All money is stored as whole **cents** (`€4.01` is `401`). Conversion happens only when reading what the player typed and when showing amounts.                                                                                                | Decimal fractions are not exact in binary floating point; whole numbers are, so totals always reconcile to the cent.     |
| 2   | Demand compares whole cents: 10 if `price <= ref`, 5 if `ref < price <= 2 × ref`, otherwise 0.                                                                                                                                                 | Makes the €4.01 and €8.01 boundaries exact, with no rounding.                                                            |
| 3   | Every price starts each run at its reference price.                                                                                                                                                                                            | Every price is valid from the first second, and the default sells the maximum 10.                                        |
| 4   | Prices can be changed any time before a trade while the run is in progress, and stay until changed.                                                                                                                                            | Matches the brief's "set prices before trading" without forcing the player to re-enter them every day.                   |
| 5   | Buying is allowed any time while the run is in progress, and switched off once day five is traded.                                                                                                                                             | The brief says further buying must stop after day five.                                                                  |
| 6   | Trading with an empty shelf is allowed and still advances the day, recording a zero-sales receipt.                                                                                                                                             | The player is never stuck; the brief's A4 already covers "with zero stock, sell zero".                                   |
| 7   | **Day numbering:** the run starts on day 1, and `currentDay` is the day about to be traded. After the fifth trade the status is `completed`, `currentDay` stays at 5, and there are 5 history records. The screen says "5 of 5 days complete". | One clear convention: `history.length` always equals the number of days completed. Tested in `tests/domain/run.test.ts`. |
| 8   | Cost of goods sold uses the fixed unit cost.                                                                                                                                                                                                   | Unit costs never change, so there is nothing to average.                                                                 |
| 9   | Overall gain/loss = final cash + remaining stock × unit cost − €100.00. It can be negative and is shown with a sign, a colour and words ("Overall loss of …").                                                                                 | Straight from rule CT R4; colour is never the only signal, for accessibility.                                            |
| 10  | **New run** always asks for confirmation (a run always exists once the app is open). Cancel changes nothing; confirm resets to the initial state. The very first visit creates a fresh run silently.                                           | Protects the player from losing progress by accident, as A6 requires.                                                    |
| 11  | Refused actions never change state and never write to storage.                                                                                                                                                                                 | The brief: "Rejected actions leave existing data unchanged". Asserted by counting storage writes.                        |
| 12  | A run is one saved record, replaced in a single write.                                                                                                                                                                                         | A single `localStorage.setItem` either happens or does not, so there are no half-saved days.                             |
| 13  | The menu lives in `spec/catalogue.json` and is checked at startup (at least 3 products, unique ids, positive whole-cent cost and reference price).                                                                                             | One source of truth for the menu, used by the app and by the tests.                                                      |
| 14  | No randomness, network, accounts, external services or AI features.                                                                                                                                                                            | Out of scope for the first release; ESLint forbids `Math.random` and `Date` in the domain.                               |

## New ambiguities found while building

| #   | Decision                                                                                                                                                                                                                                                                             | Reason                                                                                                                                             |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 15  | **Comma decimals are accepted:** `4,50` means €4.50, the same as `4.50`. Thousands separators are not accepted (`1,000.00` is refused).                                                                                                                                              | Players in Portugal and much of Europe write a decimal comma; refusing it would feel like a bug. Allowing only one separator keeps it unambiguous. |
| 16  | Spaces around a typed quantity or price are ignored. A `€` sign, scientific notation (`1e2`), a leading dot (`.50`) or a trailing dot (`4.`) are refused.                                                                                                                            | Forgiving about harmless spaces, strict about anything that could be misread.                                                                      |
| 17  | **Order limit:** one order is 1 to 1,000 units.                                                                                                                                                                                                                                      | Keeps every total small and exact. With €100 start cash and at most 10 sales per item per day, nobody can afford 1,000 units anyway.               |
| 18  | **Price ceiling:** at most €1,000.00.                                                                                                                                                                                                                                                | Stops absurd numbers; any price above twice the reference already sells nothing, so the cap never changes a result.                                |
| 19  | The quantity box starts at 10.                                                                                                                                                                                                                                                       | 10 is the most an item can sell in a day, a sensible first order.                                                                                  |
| 20  | A typed price is applied by **Enter**, **Set price**, a **±10 c nudge**, or automatically when **Open for the day** is pressed. Leaving the box does not apply it.                                                                                                                   | What you see is what you trade with. Applying on blur moved the layout under the mouse in testing and swallowed the click on Open.                 |
| 21  | While any price box holds an invalid value, **Open for the day** is disabled and the reason is shown.                                                                                                                                                                                | Avoids trading with an old price while the screen shows a different, broken one.                                                                   |
| 22  | **Damaged save:** the app shows what is wrong and does nothing else. Only when the player presses **Start a fresh run** is the old text copied to `brew-and-byte:run:v1:unreadable-backup`, then a new run is saved. If the backup cannot be written, the old save is left in place. | Loading stays read-only, and no data is ever destroyed silently.                                                                                   |
| 23  | **Storage blocked entirely** (some private modes): the game runs in memory with a visible warning. **Storage failing on a save** (e.g. full): the action is refused with a message and nothing changes.                                                                              | The first keeps the game playable; the second keeps the screen honest about what is saved.                                                         |
| 24  | Saved data is validated twice: its shape (types) in `src/storage/saveFormat.ts`, then the game's rules (receipts add up, history matches the day, …) in `src/domain/invariants.ts`.                                                                                                  | A save that "looks right" but breaks a rule is still refused, so a damaged file can never replay or corrupt a day.                                 |
| 25  | **Reconciliation wording.** The brief's check "sum of daily gross profits minus the cost of stock still unsold" equals the change in **cash** (final cash − €100). The overall gain/loss itself equals the plain sum of daily gross profit. Both are tested.                         | Buying swaps cash for stock at equal value, so only trading changes cash + stock value. This reading makes both statements true.                   |
| 26  | Prices and stock are also refused if a product id is not on the menu (`UnknownProduct`).                                                                                                                                                                                             | The interface never sends one, but the rules stay safe on their own.                                                                               |

## Tooling

| Decision                                                                                                                                                                                          | Reason                                                                                                                                    |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Exact versions are pinned in `package.json` and `package-lock.json`; install with `npm ci`.                                                                                                       | Everyone, including CI, gets the same tools.                                                                                              |
| `@playwright/test` is 1.56.1, and an npm `overrides` entry keeps `@axe-core/playwright` on the same `playwright-core`.                                                                            | One browser engine version for all browser tests.                                                                                         |
| TypeScript 5.9, Vite 7, Vitest 4.1, ESLint 9.                                                                                                                                                     | All support Node 20.19+ (the brief asks for Node 20+); newer majors either dropped Node 20 or are not yet supported by typescript-eslint. |
| The lockfile was generated with npm 11 because npm 10 hit an internal resolver bug on this dependency set. `npm ci` with npm 10 (the version bundled with Node 20/22) installs from it correctly. | Verified locally with npm 10.9.4 and in CI.                                                                                               |
| The context file is kept at the repository root as `CAMPUS_TYCOON_CONTEXT.md`, the name the repository layout asks for.                                                                           | Matches the specified layout.                                                                                                             |
